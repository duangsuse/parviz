# parviz

浏览器里的递归下降解析器实验台：用一套很小的元语言写文法，实时得到 CST、语法树、代码高亮、错误恢复和【逐字符解析轨迹】

同一套引擎上，自带一个可求值且比较完整的 Lisp！

界面cheatsheet：

- 输入区失焦自动解析；`Ctrl+Enter` 用 `@walk` 指定的 walker 执行。
- 点一个位置，`→` 步进，`Shift+→` 连返回一起看；`F8` 执行到断点/判断，`F11` 下一条语法语句（`@stmt` 声明的规则）。
- 树节点单击按当前工具处理，双击总是打 `[n]` 标记；`F12` 控制台里 `$1` 是输入流，`$2` 最后悬停节点，`$4` 最近结果，`$5..` 是AST标记。
- 规则区本身也用元语言描述（`META` v2），所以规则区有高亮、引用跳转和“未定义规则”提示。
- `p5.html`：不带调试器的独立页面，用 Lisp 写 p5.js 草图（toplevel = setup，`tick` = draw，自动 await，双击函数名设断点），见第四章。

# 一、元语言：组合子、`/re/`

## 1.1 一条精炼的规则

文法是一行一条规则，**第一条就是起始规则**

```text
@skip /re/ | none           # 词法跳过（空白 / 注释）
@color Name=B Key=P ...     # 颜色：B 蓝、Y 黄、G 绿、R 红、P 紫
@walk lisp                  # Ctrl+Enter 使用的 walker
@stmt Stmt                  # 哪条规则算一条语句（F11 的边界、Doc.stmts 的来源）
```

规则体是隐式序列。每个 item 可以：

- 是 `/re/`、`"字面量"`、小写关键字、大写规则引用、`Recur`，或 `( ... )` 分组；
- 后面跟后缀操作符 `<` `+` `*` `?`，或 `:func` / `:par` / `:setRecur`；
- 失败回溯，`seq` 失败回到组起点，`alt` 失败回到选择起点再试下一项。

**值的形状**：0 个是 `undefined`，1 个直接是那个值，多个是数组。`+` / `*` 匹配 0 次时值是 `[]`。分隔符和 `err` 节点不进值。`:par` 默认取内层的值。


## 1.2 `+`、`*`、`-`、`<`（对应 `?`）

| 写法 | 含义 | 要点 |
| --- | --- | --- |
| `(A B <)` | 有序选择 | 按书写顺序试，第一个成功者胜；每一项可以是一个序列 |
| `(Value Sep +)` | join，0~N 个 | **最后一项是分隔符**，不是“前一项重复一次以上” |
| `(A B *)` | 重复，0~N 次 | 重复整个序列 `(A B)`；不处理分隔符语义 |
| `(A Value B :par)` | 配对 | 括号提示、嵌套提取、错误恢复 |
| `(kw1 kw2 -)` | 关键字集合 | 最长优先匹配；`-` 表示可以什么都不吃，并登记补齐候选 |
| `(Ops (- "+" "-"; "*" "/" -))` | TDOP 算符表 | `;` 分级，越往后越紧，全部左结合；末尾 `-` 收尾 |
| `(A B ?)` | 可选 | 整个序列出现 0 或 1 次；缺省值是 `undefined` |
| `(A :setRecur)` + `Recur` | 递归起点 | `Recur` 调用最近的 `:setRecur`；不支持左递归 |

### `<`：有序选择

```text
Val  (Num Bool Str Raw <)
```

依次尝试 `Num`、`Bool`、`Str`、`Raw`。前一项即使吃掉了一些字符，失败后也会回到 `(` 的位置。**顺序就是优先级**

### `+`：带分隔符的 0~N 连接

```text
Ini   (Line /\r?\n/ +) :ini
Cols  (Col "," +)
```

如果分隔符前有多项，前面的项先组成一个序列，例如 `(A B C +)` 是 `(A B)` 与 `C` 的连接。

### `*`：纯重复

```text
Sheet  (Rule *)      # 0~N 条 Rule
Value  (Val *)       # 0~N 个 Val
```

`*` 在 `:par` 或顶层遇到失败时，会跳过一块并插入 `err` 节点继续读

### `?`：可选

注意：如果外层序列把多个值收集成数组，这个位置就是数组里的一个 `undefined`

```text
(Where ?)            # 没有 WHERE 也行
(";" ?)              # 分号可省
```

### `-`：有两意义

`-` 不是通用的“空解析器”，它只出现在两种地方：

1. **关键字集合**：`Kws (pub priv pro override -)`
   - 按最长优先lookahead其中一个关键字；
   - 当前解析位置会登记到 `ss.comp`，供 UI 的补齐菜单使用；
   - 重复 `(Kws Kws)` 就变成“必须匹配一个关键字”。

2. **算符表**：`(Atom (- "OR"; "AND"; "="; "+" "-"; "*" "/" -))`
   - 开头的 `(-` 标记算符表，结尾的 `-` 标记结束；
   - `;` 分隔优先级，**越往后结合越紧**；
   - 全部左结合，不支持右结合；
   - 表中的算符修饰紧挨在它前面的操作数解析器；
   - 每个结合产生一个 `bin` 节点，值是 `[算符, 左值, 右值]`；
   - 右边缺项时退回到算符之前，把错误留给外层。

写 `(A -)` 或把 `-` 当普通 item 会直接在编译文法时报错。

## 1.3 `/re/`

`/re/` 是粘性正则：只在**当前输入位置**匹配，不会向后搜索。正则本身不跳过空白；真正的“词法空白”由 `@skip` 在每次 token 尝试前处理。

```text
@skip /(?:[ \t]+|[;#][^\n]*)+/
```

- `@skip` 的正则要能一次吃掉一段（用 `+`），否则两个 token 之间可能有剩余空白，最后报“后面多出了 …”。
- `@skip some [/re/]`：比 `none` 多的只是——在**没有 `@color` 规则**的解析状态里仍然自动跳空白（默认 `\s+`，或给出的正则）；一旦进入有 `@color` 的规则（如字符串、数字这类 token 规则），内部不再自动跳，空白原样保留。进入有色规则之前的空白由外层先跳掉。
- `@skip none` 完全关闭跳过。URL 示例就是自己用 `\s` 和 `[^...]` 管住空白。
- `/re/` 里的 `/` 要写成 `\/`；字符类里的 `/` 可以不转义。
- 正则里可以用 `${P}` 插入规则参数，参数必须是字符串字面量；插入时按正则字符转义。CSV/TSV 复用同一组规则就是靠这个：

```text
Table(D)  (Row(D) /\r?\n/ +) :table
Row(D)    (Field(D) D +)
Num(D)    /-?\d+(?:\.\d+)?(?=[${D}\r\n]|$)/ :num

Csv  Table(",")
Tsv  Table("\t")
```

`@color` 里的规则名按规则染色，`kw` 给关键字染色；`:num` / `:str` 只做值转换，颜色仍由 `@color` 决定。

小写词是关键字，这是元语言的硬规则；所以 SQL 示例把大写关键字写成 `"SELECT"`、`"FROM"`、`"AS"` 这样的字面量。`lit` 在结尾是单词字符时会避免 `true` 匹配到 `truex`。

## 1.4 特殊用法

### `:par`：配对、嵌套扫描与错误恢复

```text
Sect   ("[" Name "]" :par)

Rule   (Sel "," +) ("{" (Decl *) "}" :par)
```

- 内层的值默认就是 `:par` 的值；要换 tag 再套 `:tag("()")`；
- 开符和闭符都是字符串字面量时，会登记到 `g.pairs`。`skipTo` 用它做嵌套深度扫描，并跳过字符串里的括号；
- 内层出错时，`join` 会落到最近的分隔符或闭符；错误挂在开符和闭符上；正则不会自动登记配对关系。

### `:setRecur` / `Recur`：把递归钉在某一层

```text
Json  ((Val Lit null true false <) :setRecur)


Val   (
  ("[" (Recur "," +) "]" :par) 
  ("{" (Str ":" Recur "," +) "}" :par :obj) <)
```

`Recur` 不是“起始规则”，而是**最近的 `:setRecur` 包住的那个解析器**。这里 `Recur` 会重新进入 `Json`，于是数组和对象可以无限嵌套。`:setRecur` 可以嵌套，取最近的一层。

引擎会捕获 `RangeError` 并报“递归过深（左递归？）”。

### `:func`：解析后处理

`:func` 接收 `(value, node, ss)`，返回值替换原值；返回 `FAIL` 则视为这次匹配失败（位置回退，记入期望集合）。

内置常用：

| 写法 | 作用 |
| --- | --- |
| `:tag("()")` | 把值包成 `[tag, ...值]`；值是数组就展开，`undefined` 变 `[tag]` |
| `:num` / `:int` | `Number` / `parseInt` |
| `:str` | `JSON.parse`，失败则去掉首尾引号 |
| `:unq` | CSV 的 `""` 反转义 |
| `:text` | 原样截取源码区间，保留空白与引号 |

| 特殊写法 | 作用 |
| --- | --- |
| `:table` | 首行当表头，其余行变对象数组 |
| `:obj` | `Object.fromEntries`，把 `[键, 值]` 数组变成对象 |
| `:chainl` | 把 `[首项, [[算符, 项]...]]` 从左往右折叠成数值 |
| `:infix` | 把 TDOP 的 `bin` 节点转成 Lisp 调用 `[算符 左 右]` |

自定义函数通过 `grammar(text, { funcs })` 传入，或先 `Object.assign(P.funcs, funcs)` 再编译。`extra.js` 用的就是后者。

PEG 风格的递归下降不能直接写 `Sum ← Sum "+" Prod`，会无限递归。`lisp.js` 的朴素计算器把它写成链：

```text
Sum   Prod ((Add Prod) *) :chainl
Prod  Atom ((Mul Atom) *) :chainl
Add   /[+-]/
Mul   /[*\/]/
```

注意，这里处理优先级没有用 `:setRecur`

`*` 先把 `(Add Prod)` 重复出来，`:chainl` 再从左到右折叠成数值。这个文法不需要作用域，也不需要专门 walker。

# 二、API 速查

```js
const P = require('./parse.js')
const L = require('./lisp.js')

// 1) 编译文法
const g = P.grammar(rulesText)
console.log(g.errs)        // 文法自身的错误
console.log(g.start)       // 起始解析器

// 2) 准备输入流并解析。输入流支持 onedit 和高亮/报错收集
const ss = P.feed(srcText, 'feed$A')
const value = P.eat(g, ss)

console.log(value)         // 根值
console.log(ss.tree)       // CST（Node）
console.log(ss.errs)       // [{a,b,msg,node}]
console.log(ss.sloc(ss.tree))  // './feed$A:1:0'

// 3) Lisp 求值
const r = L.run(value)     // { value, log, steps } 或 { err, a, b, log }（a/b = 出错处的源码跨度）
console.log(L.show(r.value))
```

- `P.grammar(text, { funcs })` 在编译时合并 `P.funcs`；自定义 `:func` 要在编译前注册。
- `P.feed(src, file, i=0)` 返回 `ss`：`ss(n)` 偷看/吃掉 `n` 个字符（负数表示吃掉），`ss.i` 是当前位置，`ss.sloc` / `ss.nodeOf` / `ss.marks` / `ss.onedit` / `ss.comp` 是 UI 和调试接口。
- `P.eat(g, ss)` 会设置 `ss.tree`、`ss.errs`、`ss.value`，返回根值。
- `L.run(ast)` 最多执行 300000 步；`L.steps(ast)` 返回可逐步迭代的生成器；`L.node(ast, program)` 在完整程序环境里单独求值某个节点。
- 脱离调试器独立运行（`p5.html` 用的）：`L.host = { has, get, last?, log?, error?, pause?, alive? }` 提供宿主名字（`L.hostOf(层...)` 把几层对象叠成 `has/get`）；`await L.start(program, log)` 以顶层程序为入口，同步跑到底，遇到 Promise / 断点才转异步；`L.callback(f, args)` 以一个 Lisp 函数为入口（返回值或 Promise）。见 2.9。
- `P.walkers.lisp` / `P.walkers.calc` 是 `@walk` 可用的 walker；`P.examples` 里是内置示例，`extra.js` 通过 `(P) => ({ funcs, examples })` 追加。

`extra.js` 里的 URL、迷你脚本等示例还会用到：

- `@skip none` 与 `:dec`（`decodeURIComponent`）；
- `:chainl` 的朴素左结合；
- `:apply` / `:infix` / `:arg2nth` / `:fn` / `:let` 把迷你脚本直接编译成 Lisp AST，再用 `@walk calc` 执行。

它们都可以在页面示例下拉框里直接切换查看。

# 三、Lisp：`=>`、`-`/`->`、`.`/`..` 的创新

下面的篇幅综合来看还是挺短的，也定好了许多细节。

> parviz 的Lisp风格更接近Clojure，但非常的【不死板】

walker 的公开入口是 `P.walkers.lisp`：`run(program)`、`steps(ast)`、`node(ast, program)`、`show(value)`。`@walk calc` 是同一个 walker 的变体。

`steps` 产出的事件是 `{ ph, a, b, x?, f?, args?, v?, c?, t?, p? }`：`ph` 是 `in`/`out`/`ret`/`if`/`await`，`a`/`b` 是源码跨度（值节点自带，不出现 CST 节点）；结束值是 `{ value }` 或 `{ err, a, b }`。

程序取最后一句的值，单个四则运算不需要 `OK ret`。

## 2.1 一切皆 tag

Lisp 的 AST 不是类继承，而是“标签式多态调用”：

```text
[fact 5]          →  ["[]", ["$", "fact"], 5]       // 语句位置，求值时等价于 ["()", ...]
(fact 5)          →  ["()", ["$", "fact"], 5]
(=> (a b) e)      →  ["=>", ["..", "a", "b"], e]
[- f e]           →  ["=", "f", e]                  // 定义，之后不能被 -> 改变
[-> x e]          →  ["->", "x", e]                 // 局部赋值，没有就初始化
{name "parviz"}   →  ["{}", ["name", "parviz"]]
[1 2 3]           →  ["[]", 1, 2, 3]                // 表达式位置 = 数组
(c)? a Or b       →  ["?", c, a, b]
```

标签 `"$"` 是名字引用（作用域内，由 Lexscope 绑定），`"$$"` 是全局键（解析期确认不在任何作用域里的内建 / 全局名，运行时直接查内建表），`""` 是字符串字面量。这三种是最常见的节点，所以都做成叶子：不分配 kids 临时数组，`ns` 共用一个空数组，`ev` 里不经 `Walk` 表（统计工具见 `tools/freq.js`）。`".."` 是语句/参数表，`"()"` 是调用，`"[]"` 在语句位置也是调用。`"."`、`"?"`、`"="`、`"->"`、`"=>"`、`"{}"` 都只是 tag；walker 的 `Walk` 表按 tag 取生成器：

```js
const Walk = {
  '$': function* (x, env) { /* 名字解析 */ },
  '': function* (x, env) { /* 字符串字面 */ },
  '()': function* (x, env) { /* 调用 */ },
  '[]': function* (x, env, stmt) { /* 语句=调用，表达式=数组 */ },
  '..': function* (x, env) { /* 逐句执行 */ },
  '{}': function* (x, env) { /* 对象 */ },
  '?': function* (x, env) { /* if */ },
  '=>': function* (x, env) { /* lambda */ },
  '.': function* (x, env) { /* 键取值 o.k；或把基座插为第一个实参 */ },
  '=': function* (x, env) { /* 定义 [- a e] */ },
  '->': function* (x, env) { /* 局部赋值 [-> a e] */ },
}
```

解析器用 Lexscope 组合作用域；walker 只关心 tag。两者可以分开替换。

## 2.2 `=>`：lambda

两种括号、两种参数表都行：

```lisp
(=> (a b) (+ a b))
[=> [a b] (+ a b)]
```

调用：

```lisp
(w@ ((=> (x) (* x x)) 7))                 # write 49

(w@ (((=> (a) (=> (b) (+ a b))) 2) 3))    # 5
```

要点：

- `=>` 在 `:fn` 处闭合作用域：参数、函数体内的 `[- ...]` 局部定义都在这个 lambda 的环境里；外层变量仍然可见（闭包）。
- 柯里化就是嵌套 lambda；没有单独的“多参柯里化”魔法。
- 函数体可以有多条语句，但**多语句必须用 `OK` 返回值**
- 多语句函数体没有 `OK` 时，副作用照做，但值是 `NO`，并在 log 里给出“多语句缺少 OK 返回”。
- 参数不足时，缺少的参数绑定为 `NO`，不会报参数个数错误。

## 2.3 `-` 与 `->`：定义与赋值

`(- 名字 值)` 和 `[- 名字 值]` 都产生 `["=", 名字, 值]`：在当前位置的环境里**定义**，并返回值，之后不能被 `->` 改变（Lexscope 在解析期检查，同一作用域里 `->` 它会在名字上报错）。值是匿名 lambda 时，会把函数名补上，便于显示和调试。减法没有 `-` 内建了：写成加负数 `(+ a (neg b))`，或用下面的中缀。

```lisp
[- f (=> (a b) (+ a b))]
(OK (f 2 3))          # 5
```

`def` 是语法糖，和 `-` + `=>` 得到相同 AST：

```lisp
def sq(x) (* x x)

# 等价写法：
[- sq (=> (x) (* x x))]

def multi(a b):
  [- c (+ a b)]
  (OK c)
...

(sq 6)..(w@)          # 36
```

注意 `def` 的体需要多条语句时用 `...` 视为end，并且有 `:` 开头。

`[- ...]` 在表达式位置也是定义，因为文法里 `Let` 排在 `Brk` 前面，且用 `(?=\s*-\s+名字\s)` 前瞻：

```lisp
(w@ [- x 1] x)     # 1 1
```

作用域：

- 顶层 `Lisp (Stmt *) :global :tag("..")` 绑定顶层定义；
- 函数调用创建子 `Env`，参数和局部 `-` / `->` 不会泄漏到外层；
- `[-> x e]` 是当前作用域的局部赋值：`x` 没有就初始化，有就覆盖；外层同名变量不受影响；
- `[-> x e]`：`e` 不是对象字面量时是整体赋值；`e` 是对象字面量时是**部分赋值**：把字面量里的键并进 `x` 现有的值（没有就从空对象开始），结果是当前作用域里一个新对象，外层的 `x` 不变：`[-> u {b 3}]`；
- 状态对象的原地修改写成 `o..[-> {…}]` / `o..[-> "k" v]`：`..` 是管道，把 `o` 插进 `->` 的第一个实参；这里的 `->` 是内建函数，把键并进 `o` 本身（同一个对象，别处也看得到）并返回它，所以闭包、回调里也能改外层的状态：`(- s {n 0})` 之后 `s..[-> {n (> s.n + 1)}]`；
- 引用解析不到、又不是内建时，解析阶段就会在 `:global` 报“未定义 xxx”；
- 函数体里的递归引用能解析到外层的 `def` / `- f`，因为 lambda 的 `env` 指向定义处的外层环境。

## 2.4 `.`：取键、方法调用、管道

`.` 后面跟一个键就是取键，跟一个调用就是 JS 的方法调用（`o.[k a]` 即 `[o.k a]`，`k` 是键，不是作用域里的名字）：

```lisp
(- o {f len})
(w@ o.f)                 # <builtin len>   取键
(w@ o.[f [1 2 3]])       # 3               `[o.f [1 2 3]]`，JS 方法的 this 是 o
(w@ o.(f "ab"))          # 2               同一个机制
(w@ [1 2 3].len)         # NO              数组没有 len 这个键
```

管道写两个点：`x..(f a)` 即 `(f x a)`，`x..[f a]` 即 `[f x a]`：

```lisp
(w@ [1 2 3]..(len))                    # 3
(w@ 5..(+ 2)..[* 10])                  # 70
(w@ [1 2 3]..(map (=> (x) (* x x))))   # [1 4 9]
```

要点：

- `o.k` 取键；`o.[k a]` / `o.(k a)` 是 `[o.k a]`：`k` 是键（不查作用域），JS 方法的 `this` 是 `o`；
- `x..(f a)` / `x..[f a]` 是管道：基座插到第一个实参；
- **语句位置**：`[f a b]` 是调用；`[len a]..[+ 1]` 里 `[len a]` 在语句位置，先算 `(len a)`，等价于 `(+ (len a) 1)`；同样的基座在**表达式位置**是数组；
- 管道后面必须是一个调用 `( … )` / `[ … ]`，`x..(=> ...)` 不合法，因为 `(=> ...)` 是 `Lam`，不是 `List`；
- 脱糖后的形式在单独的「值」Tab 里（与 CST 树分开，见 `ui/doc.js` 的 `val`）：`[3 14 15 9 26]..(big 10)` 显示为 `[big [.. 3 14 15 9 26] 10]`。

## 2.5 `{}`：对象

```lisp
(w@ {name "parviz" langs ["js" "lisp"]})
# {name "parviz" langs ["js" "lisp"]}

(w@ {"a b" 1 n 2})
# {a b 1 n 2}
```

- 键可以是裸符号（`SYM+`，不能含 `()[]{}",;?.` 和空白），也可以是带引号的字符串；带引号的键通过 `:str` 变成真正的字符串，所以可以含空格。
- 值可以是任意表达式；键不参与求值；重复键后写覆盖先写。
- 取值写 `obj.k` 或 `obj."a b"`（脱糖成 `(get obj "k")`），列键用 `(keys obj)`。
- “改键”：`o..[-> {"k" "new"}]` 把键并进 `o` 本身并返回 `o`（原地修改，见 2.3）；`(- ob {})` 之后 `ob.k` 在改之前是 `NO`；`{}..[-> {…}]` 对字面量同样有效。

## 2.6 语句级并列与中缀

- **语句级并列 = 自动插括号**：同一行里语句开头并列的表达式，相当于外面补一层括号，换行或 `;` 结束语句（类似 JS 的自动分号）。`a b` 即 `(a b)`；`(a) b` 即 `((a) b)`；`c.d e f` 即 `(c.d e f)`（`c.d` 先取键，再把它当函数调用），所以 `a b; c.d e f` 是两个调用。`;` 在括号内部与空白等价。
- **注释与字面量**：`#` 到行尾，`#@ … @#` 可跨多行。但 `#` 后面紧跟 3/4/6/8 位十六进制数、并在分隔符处结束时是**颜色字面量**（`#66ccff`，值是字符串，可直接给 `fill`），不是注释；`./a/b.wtf`、`../x` 是**路径字面量**（也是字符串）。所以 `#bad` 是颜色，`# bad` 才是注释。
- **中缀只在头是 `>` 的括号里**：`(> …)` 和 `[> …]` 里写成“项 运算符 项 运算符 项 …”，运算符是 `+ - * / %` 和 `< <= > >= == !=`；优先级 比较 < `+ -` < `* / %`，同级左结合；`2x` 是 `(* 2 x)`。结果就是整个式子的值——算术给数，比较给布尔，一项就是那一项。编译时直接脱糖成普通调用，减法编译成加负数：`(> 2x + 3y - 7)` 即 `(+ (+ (* 2 x) (* 3 y)) (neg 7))`。这里的 `>` 是语法而不是比较函数；`(> a b)`（项与项之间没有运算符）报错。别处没有中缀：`(+ a + b)` 只是把 `+` 当参数的普通调用。
- **比较与逻辑**同样用它：`(> n <= 1)? 1 Or …`、`[> x != y]?`；`both`、`isnt` 仍是普通函数。

```lisp
(- x 2)
(- y 1)
(w@ (> 2x + 3y - 7))        # 0
(w@ [> 2x + 3y > 3])        # true
(w@ (> x != y) (> 1 + 2 * 3))   # true 7
```

## 2.7 `? ... Or ...`、`NO`、`OK`

### 条件表达式和NO

文法里 `? ... Or ...` 是 `["?", 条件, 真值, 假值]`。`Or` 在这里是字面量分隔符；注意 `Name` 规则的前瞻排除了单独的 `Or`

```lisp
(> x > 10)? x Or NO

(w@ ((=> (x) (> x > 3)? "big" Or "small") 5))   # big
```

真值判断只把 `NO`、`false`、`null` 当假；`0` 和 `""` 都是真。比较运算返回 JS 布尔值

`NO` 是“没有值”的哨兵：

- `(at arr i)` 越界、`(get obj k)` 缺键都返回 `NO`；
- `(isnt NO)` → `true`；`(both a b)` 是 `a and b`（`a` 为假则取 `a`，否则取 `b`）；
- `mapNotNO` 会过滤掉回调返回的 `NO`。

```lisp
(w@ (at [1] 9))       # NO
(w@ [1 20 3 40]..(mapNotNO (=> (x) (> x > 10)? x Or NO)))   # [20 40]
```

### `OK`

`OK` 是流控返回：它抛出 `Ret`，由函数体/程序的 `body` 捕获。

- 单语句体直接取该语句的值；
- 多语句体/程序必须用 `(OK value)` 返回，否则最后值是 `NO` 并记录警告；
- `@walk calc` 使用 `last=true`，多语句程序取最后一句的值，所以四则运算示例不需要 `OK`。

```lisp
[- add (=> (a b) [- s (+ a b)] (OK s))]
(OK (add 2 3))     # 5
```

## 2.8 综合示例

这段就是 `lisp.js` 里的 `Lisp` 示例，覆盖了 `-`、`=>`、`def`、`.k`、`..()`、`{}`、`[]`、`? ... Or ...`、`NO`、`OK`：

```lisp
# 语句位置的 [..] 是调用；x..(f a) 是管道 (f x a)；o.k 取键，o.[k a] 即 [o.k a]（方法调用）
[- big (=> (xs n) xs..(mapNotNO (=> (x) (> x > n)? x Or NO)))]
def fact(n) (> n <= 1)? 1 Or (> n * (fact (> n - 1)))
[- inc1 (=> (a) [len a]..[+ 1])]
(- user {name "parviz" langs ["js" "lisp"]})
(w@ "fact 5 =" (fact 5) "big:" [3 14 15 9 26]..(big 10) user.name (inc1 [1 2 3]))
(OK [123]..(mapNotNO (=> (x) (> x > 10)? x Or NO))..[at 0])
```

运行结果：

```text
fact 5 = 120 big: [14 15 26] parviz 4
```

`w@` 每次求值会往 `log` 里写一行，并返回最后一个实参（`tee` 命令）。

逐段看：

- `big` 接收数组 `xs` 和阈值 `n`，用 `..()` 把 `xs` 插到 `mapNotNO` 的第一个实参位置；回调 `(> x > n)? x Or NO` 不满足时返回 `NO`，`mapNotNO` 过滤掉。
- `def fact(n)` 定义递归函数；`(> n <= 1)? 1 Or (> n * (fact (> n - 1)))` 是条件表达式。
- `inc1` 用 `[len a]..[+ 1]`：先取长度，再作为 `+` 的第一个实参。
- `user` 是对象；`user.name` 是 `(get user "name")`，键含空格时写 `user."a b"`。
- `w@` 的参数里，`[3 14 15 9 26]` 是数组，`[123]` 也是数组；最后的 `OK` 让程序返回 `123`，而不是 `NO`。

| 类别 | 名字 |
| --- | --- |
| 算术 | `+` `*` `/` `%` `neg`（减法、运算式写成 `(> a - b)`） |
| 比较 | `>` `<` `>=` `<=` `==` `!=`（二元；源码里写成 `(> a <= b)`，不能直接 `(> a b)`） |
| 逻辑 | `isnt` `both` |
| 数组 / 对象 | `at` `get` `len` `keys` `list` `concat` `push` `range` `sum`；`o..[-> {…}]`（原地合并，见 2.3） |
| 高阶 | `map` `filter` `mapNotNO` `reduce` `each`（`(each xs (=> (x i) ...))`，返回 `xs`） |
| 流控 / 输出 | `OK` `w@` |
| JS 互操作 | `new`（`(new Date 0)`）`wait`（`(wait 500)` 毫秒后兑现的 Promise） |
| 常量 | `NO` `true` `false` `null` |

## 2.9 调 JS：宿主、自动 await、回调

有宿主（`L.host`）时，内建和作用域里都找不到的名字向宿主要（浏览器里就是 `window`；`p5.html` 再叠加 p5 实例）。没有宿主时语言是封闭的，`console` 在解析期就是"未定义"。

```lisp
[console.log "hi" 123 (=>() 456)]        # hi 123 ƒ；Lisp 函数交给 JS 时变成回调
(- r (Promise.resolve 42))               # 返回 Promise 的调用自动 await，r 是 42
[setTimeout (=> () [console.log "later"]) 500]
(- d (new Date 0))
(w@ (d.getTime) Math.PI)                 # 方法绑定到所属对象，this 正确
```

- `a.f` 取 `a` 的键 `f`；`[a.f x y]` 或 `(a.f x y)` 就是调用，JS 方法的 `this` 是 `a`。大写开头的函数（`Promise`、`Date`）当构造函数，不绑定，`Promise.resolve` 这类静态成员照常可取。
- 值互转：`NO` ↔ `undefined`；Lisp 函数 → JS 回调（同一函数永远是同一个包装，可以 `removeEventListener`）；回调里出错交给 `host.error`。
- 自动 await：任何调用返回 Promise，就挂起当前执行，兑现后继续；被拒绝则报错并指到调用处。同步驱动（`L.run`、调试器逐步执行）不会等，Promise 原样作为值。
- `host.last` 为真时，函数体取最后一句的值，不要求 `OK`（`OK` 仍可提前返回）。
- `host.pause(事件)` 返回 Promise 就在该事件挂起到它兑现（断点），`host.alive()` 返回 `false` 则放弃执行（停止）。

# 四、`p5.html`：用 Lisp 写 p5.js

`p5.html` 不带调试器视图：左边编辑器（高亮同主页）+ Console（`#out`，与调试器共用 `ui/console.js`：错误行/暂停行悬停会在源码上连线、点击跳转，错误位置有 `E1` 角标），右边 Preview；`Ctrl+Enter` 运行，`Ctrl+Shift+Enter` 停止，`F8` 断点处继续。下拉框里有 7 个示例。p5.js 取自 CDN。多项式一律写成头是运算符的括号：`(> a + 2b)`、`(> a - b)`，比较写 `[> a <= b]?`（见 2.6）。

- **toplevel 语句就是 setup**：在 p5 的 `setup` 里跑一遍，可以直接 `createCanvas 400 300`，也可以 `wait 500` 顺序等待（等待期间不 draw）。
- **`tick` / `see` 注册每帧函数**：`tick.{ … }` 每个重画帧（draw）跑一次，`see.{ … }` 是**物理帧**，固定频率（默认 20 Hz，`frameRate 60 20` 的第二个数），与 fps 无关；都返回句柄，随时随地可以注册（包括在事件处理器、别的 tick 里），`[off h]` 取消。`.{ … }` 是追加成最后一个实参的回调块，块里是**语句**（同一行并列即调用，隐式参数叫 `u`）。处理器里 await 过（返回了 Promise）就占用自己，没跑完前跳过后续帧，等价于一个协程。`(tick 30 f)` 仍可限制 tick 的触发次数。
- **`on "事件" f`**：`mousePressed` `keyPressed` `windowResized` 等 p5 事件；同一事件可注册多个，同样返回句柄给 `off`。
- **鼠标**：`mouseX` / `mouseY` 只在鼠标位于画布内时更新（编辑器 / 控制台上移动不再改它们）；在画布内按下后拖出画布仍会跟随，直到松开。
- **名字**：`circle` `fill` 这类函数，`mouseX` `width` 这类变量（每次引用读最新值），`PI` `CENTER` 这类常量，都是直接可用的名字；出错的处理器会被摘掉并报在 Console。名字优先级：Lisp 内建 > 作用域 > 本页的 `tick on off scope remap p` > p5 实例 > `window`。
- **和 p5 同名的 Lisp 函数**（`map` `push` `get` `str`…）：Lisp 优先；p5 的版本走实例 `p`：`(p.map v 0 1 0 100)`、`[p.push]`。常用的两个有别名：`remap` = p5 的 `map`，`(scope (=> () ...))` = `push()` + 函数体 + `pop()`（出错也会 `pop`）。
- **状态放进对象**：名字是不可变绑定，闭包里改不了外层的 `->`；会变的状态写成 `(- ball {x 0 vx 3})`，用 `ball..[-> {x (> ball.x + ball.vx)}]` 原地改。
- **打开/保存**：`Ctrl+E` 打开目录树（Chrome 上直接用 File System Access 句柄，其他浏览器退回 `<input type=file>`），点文件即打开、`Ctrl+S` 写回原文件（没有句柄就下载 `.lisp`）；打开/切换前有未保存修改会先确认。
- **取源**：**右键**画布：选中画这一笔的调用，画一条箭头，并在**鼠标位置**弹出它那一行的第一个 Tweak 部件；想在点中的图形上设断点：先按 `F8` 再右键（见下）。**悬停**只在勾选“自动刷新”时才生效（箭头 + 直接定位源码）。没有“取源”按钮或模式。实现是 `IDEA.md` 的“亮点”（`p5/pick.js`）：请求挂在 `run.pk` 上，由**下一帧**的 `p.draw` 兑现——在用户第一笔绘制之前（不是挂在 `clearRect` 上）把鼠标下的像素涂成随机色；之后每个会写画布的 ctx 方法返回时读回，颜色变了就记下栈顶的 Lisp 调用并重新撒点，最后一个盖住它的调用就是屏幕上看到的那一笔。不额外重画，动画状态不会多走一步（只有 `noLoop` 的草图才主动 `redraw` 一次）。有 `(tweak …)` 几何声明的调用另有一份 bbox 兜底（只画一次的静态草图靠 setup 期间记下的那份）；暂停在断点上时 tick 被占用，取源也退回 bbox。
- **断点与即时求值**：新手路径 = 按 `F8`，再右键画布上的图形（状态栏有提示）→ 点中那一笔的函数设为断点；也可以双击源码里的函数名切换。函数每次返回时暂停，Console 里显示 `[f 实参] ⇒ 返回值`。键位：`F9` 继续 · `F10` 到下一条语句 · `F11` 下一帧入口 · 暂停中再按 `F8` = **取消当前断点并继续**（没暂停时 F8 再按一次取消等待右键）。暂停行下面的输入框在**这一帧的环境**里求值（`@args` 实参数组，`@ret` 返回值，`A B C…` 本次第 1 2 3… 个实参，`$A $B $C…` 同一断点上一次命中时的同位置实参，第一次是 `NO`）：`(+ x 1)` 打印结果并继续停着；`(OK 值)` 替换这次调用的返回值并继续；`? 条件` 转为**日志断点**，条件自动套一层 `(> …)`（所以直接写 `? A > 100`、`? A > $A` 表示 x 变大了）：以后条件成立时自动打印一行 `⏺ [f 实参] ⇒ 返回值`，不再暂停（单独一个 `?` 表示每次都打印；再双击函数名取消）。JS 函数（`circle`、`log`）按调用头的名字匹配。
- **控制台悬停预览**：只在鼠标悬停某一行时才检测该行文字（不悬停零开销，也没有弹层）：颜色（`#hex`、`rgb(r g b)`、`(color r g b)`，以及声明过 `(color …)` 的调用实参）直接把**这一行的文字**设成该色（很暗的颜色配浅底）；声明了 `(tweak 名字 (vec2 …) …)` 的调用 `[名字 实参…]`（暂停行、`⏺` 日志行都是这个格式）在画布上画圆点（有宽高时再加虚线框）；没写声明时，`circle` `square` `ellipse` `rect` `line` `point` `translate` 和 `fill` `stroke` `background` 按 p5 惯用的参数顺序兜底（只用于悬停预览，写了声明就以声明为准）。圆点标记记在画布上，实时运行时下一帧重画就消失；点 fps 按钮停到 0 fps（含取源触发的单次重画）或在看缓冲帧时一直留着（切换帧也保留）；`Esc`、清空控制台、重新运行、回到实时时才清掉。悬停到另一行**不清**：新位置追加到轨迹后面（按悬停先后连线，越旧越淡，同一位置移到最新，最多 200 个）。帧缓冲面板里的标记跟着面板，不随实时帧消失。悬停没有可检测内容的行不会清掉。即时求值输入框：程序化的选区 / 取源 / 刷新把焦点带走时自动抢回，只有你点输入框之外（或按 `Esc`）才离开；点输入框不再触发控制台行的“跳转源码”。
- **速率**：导航栏右侧的 `NN fps · NN Hz` 是一个按钮（取代了“停止”按钮）：fps = `p.draw` 每秒真实次数，Hz = `see` 物理帧每秒次数（没有 `see` 显示 `—`）。**点它在 0 fps（停止重画）与 `frameRate` 的值（没写是 60）之间切换**，只改这次运行，不改源码。`[frameRate 60 20]`：最多 60 fps，`see` 20 Hz。停止：`Ctrl+Shift+Enter`。
- **帧缓冲**：`Preview` 标签栏里的 `缓冲 n/N` 按钮 + 进度条。`[frameBuffer N]`（顶层，最多 600；0 关闭）开启后，每个有 tick 被触发的帧末保存：画布副本（按 CSS 尺寸，约 `W×H×4×N` 字节）、`Fbuf.snapshot` 拍的内存快照（顶层环境 + 所有已注册处理器的闭包环境；闭包记成 `<fn 名 env#i>`，指向快照里的环境；p5 实例 / 图片等宿主值只记类型名；内建不算）、以及这一帧的 p5 调用清单（名字 + 跨度 + 实参）。点按钮：没开就在源码里补 `[frameBuffer 120]`（紧跟 `createCanvas`）并选中它（不弹部件），滚轮调大小；已经在看某一帧时，点按钮等于 `● 实时`（字面量在 lambda 之外，改动会重跑，缓冲清空）。悬停进度条（横轴 = 缓冲容量，左旧右新；鼠标位置 = 帧）读取那一帧：画布换成副本，上方（预览画布之上，可拖右下角纵向调高）显示调用清单（点一项跳到源码）和快照；读帧期间暂停录制，`←` / `→` 逐帧，`Esc` 或 `● 实时` 回到实时。只读：不重放，不能在过去的帧里单步；没有 tick 的草图（只有 `on` 事件）不录。实现：`p5/fbuf.js`（快照与环形缓冲）、`p5/app.js`（`p.draw` 里 `Fbuf.begin/end`，与 `Pick` 的 `hooks.ext` 串联）。
- **常量池与热编辑**：每次解析后 `LISP.pool` 把有源码跨度的数字字面量换成格子（`Lit`），实际执行的是副本。只改了数字（打字、Tweak、滚轮）→ 按锚点 `onedit(hashline, 文本)` 改格子，不重跑、不丢状态；只有在 lambda 之外（setup 里只读一次的顶层字面量）的格子变了、或代码结构变了才重跑。来自 Tweak / 滚轮的编辑总是生效（不看“自动刷新”）；打字的编辑里，数字热编辑总是生效，需要重跑时才看“自动刷新”。空白 / 注释的改动也走这条路，不会重跑。
- **暂停时即时求值 / 替换返回值**：在 `ret` 处暂停时，Console 的暂停行下面有一个 JSON 输入框；回车按 JSON 原地改这个对象/数组（换键、换元素），恢复后下一步读取就是新值。
- **参数位置的 `[]` 是数组**：`[f ...]` 只有在语句位置才是调用，参数里要写 `(f ...)`。
- **断点**：双击源码里的函数名（Lisp 函数名，或 `circle` `log` 这类 JS 函数名）切换，所有同名处标红；该函数每次返回时在 Console 显示 `⏸ [f 实参] ⇒ 返回值` 并高亮调用处。暂停后 `F5` / `⏯ 继续` 放行、`F8` 到下一帧入口、`F11` 到下一条语句。暂停在 draw 的处理器里时，这个处理器被占用，其他 tick 照常。被 JS 同步回调的 Lisp 函数里暂停，JS 调用方不会等它。

```lisp
createCanvas 400 300
frameRate 60 20
(- ball {x 200 y 60 vy 0})
see.{                     # 物理：20 Hz
  ball..[-> {vy (> ball.vy + 1.2)  y (> ball.y + ball.vy)}]
}
tick.{                    # 重画：60 fps
  background 17 17 27
  circle ball.x ball.y 36
}
```

## 4.1 编辑器里的颜色 / 位置小工具

格式**由源码顶层的声明给出**，不再按 p5 函数名硬编码；声明里的数字是**调用处的实参下标（从 0 起）**：

```lisp
(tweak rect   (vec2 0 1) (size 2 3))   # x y；w h（size 按画布尺寸显示）
(tweak circle (vec2 0 1) (num 2))      # x y；直径
(tweak fill   (color 0 1 2 3))         # r g b [a]
(tweak rotate (angle 0))               # 一个角度（源码写弧度，滑块显示角度）
```

**对象声明**：名字换成 `{字段 …}`，下标写**字段名**；任何含这些字段的对象都匹配，组里还可以引用没列出的可选字段：

```lisp
(tweak {x y vx vy} (vec2 x y))          # (- ball {x 120 y 80 vx -3 vy 4}) 里的 x y 成为可拖的位置
(tweak {x y}       (vec2 x y) (num r))  # 有 r 时是圆（直径 r）
(tweak {r g b}     (color r g b a))
```

**推断**：没写 `(tweak …)` 的 p5 函数按内置声明（`Tweak.DEFAULT_SRC`，同一种写法：`createCanvas rect circle line text translate rotate textSize strokeWeight frameRate fill stroke background`、枚举函数、`{x y}` / `{r g b}`）直接生成源码部件，也用于 Console / 帧缓冲面板的悬停检测；写了同名声明就以你写的为准。Tweak 面板的“推断的 (tweak) 声明”折叠区列出这次用到的推断声明，**写入源码顶部**后它们就成了你的声明（可以改）。将来 p5 的文档可以直接生成这一段。

| 类别 | 例子 | 效果 |
| --- | --- | --- |
| `vec2` / `size` | `(vec2 0 1)` / `(size 2 3)` | 虚线下划线；悬停出画布缩略板（叠着当前预览，尺寸取运行中的画布，没有就取 `createCanvas`），点击或拖动改数值 |
| `color` | `(color 0 1 2 3)` | 数字底色就是该颜色；悬停出预览和原生拾色器，拾色即改 `r g b`（`a` 保留） |
| `num` / `angle` | `(num 2)` / `(angle 0)` | 数字框 / 0–360 的滑块（写回弧度） |
| `enum` | `(enum 0 LEFT CENTER RIGHT)` | 第一个数是实参下标，其余是选项；悬停出下拉菜单，选中即把那个名字写回源码（实参必须是名字，如 `textAlign CENTER CENTER`）。内置：`textAlign rectMode ellipseMode imageMode colorMode strokeCap strokeJoin textStyle` |
| 颜色字面量 | `#66ccff`、`"#f38ba8"` | 无条件识别，不需要声明；改写成 `#rrggbb`（透明度保留） |
| 开关 | `cond?.{ … }` | `?.{` 下划线绿色 = 开，红色 = 关（整块变灰）；**点 `?.{`** 在 `cond?.{ … }` 与 `(isnt cond)?.{ … }` 之间切换（只认 `?.{` 直接跟在条件后面的写法） |
| 按钮 | `def btn_xxx(): …` | 名字以 `btn_` 开头、没有参数的 `def`：函数名带下划线；**点函数名**执行这次运行里的这个函数（双击仍是断点；改了源码没重跑时执行的是旧函数） |

**Tweak 面板**（编辑器上方，`<details>` 可折叠）：源码里每个部件一行控件（位置 / 颜色 / 数字 / 角度 / 下拉 / 开关 / `▶ 执行`），改控件就是改源码，标签点一下跳到源码。**预设**：折叠条里只有一个 4 字宽的下拉，有 `【当前预设】`（改了任何值就回到它）、已存的预设、`＋ 保存为新预设`（不问名字，自动叫 `预设N`）、`－ 重命名或删除当前预设`（重命名留空 = 删除）；展开后第一行是导入输入框（粘贴即导入）、`导出` 按钮、每个预设的直达链接（名字截 3 个字，点即应用）。导出 / 导入都是**单个预设、单行 JSON**：`{"parviz":"preset","name":…,"v":{键:[值…]}}`（导出的是当前这一套参数值；导入重名自动加序号）。预设存在 `localStorage`，按文档分；键是 `声明名[下标]#第几个`，源码结构变了对不上的键会被跳过。源码结构不变时只刷新控件的值，不重建（输入框不丢焦点）。

- 声明只在顶层；写进函数体是解析期错误。下标越界会在 Console 里给一条带位置的警告。
- 只对**字面量**生成部件：`(+ x 1)`、`mouseX`、小数都不触发（`color` 按前缀匹配，`fill 243 139 168 s.a` 仍可调 RGB）。
- 改动直接写回源码并触发一次 `input`：Tweak 的编辑总是立即生效（热编辑，必要时自动重跑），不需要勾“自动刷新”。
- 没有声明的数字字面量也有最基础的部件：悬停出数字框，**滚轮**微调（同 DevTools：±1 · Shift ±10 · Alt ±0.1 · Ctrl/Cmd ±100）。每一步先让运行证明新值没问题——报错就退回上一个值，并把这个方向的区间划到上一个值（部件里显示 `区间 [lo, hi]`）。
- 弹层优先出现在文字上方（免得挡住下一行的部件）；`Esc` 或在编辑器里输入就收起。
